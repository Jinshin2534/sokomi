# 底見 (sokomi) — 靴底すり減り推定 設計書

日付: 2026-10-12

## 目的

新品時に撮った靴底の写真を基準にして、今の靴底写真と比べ、
**部位ごとのすり減りマップ**と**全体のすり減り%**を出す。

## 方針

- 推定はブラウザ内の画像解析だけで行う（サーバー・APIキー不要）。
- すり減ると溝の縁や模様が消える＝局所的なエッジの強さ（以下「模様の強さ」）が減る、を測る。
- 根拠のない数字は出さない。判定できないマスは「判定不能」と表示する。

## スタック

- Vite + 素のJS、pnpm、Vitest。開発ポート 5730。
- 写真と靴データは IndexedDB に保存する（写真は縮小 JPEG Blob で保存）。

## 画面と流れ

1. **靴一覧**: 登録済みの靴カード（名前・基準写真サムネ・最新のすり減り%）。「＋靴を登録」。
2. **基準登録**: 名前入力 → 新品の靴底を撮影/選択（`<input type=file accept=image/* capture=environment>`）→ 4点タップ → 保存。
3. **チェック**: 靴を選ぶ → 今の靴底を撮影/選択 → 4点タップ → 解析 → 結果。
4. **結果**: ヒートマップ（正規化した靴底の上に重ねる）、6部位の平均、全体%、信頼度、撮り直しの勧告。チェック結果は靴ごとに履歴として保存し、一覧に最新値を出す。

撮影ガイド（毎回表示）: 真上から・無地で靴底と色の違う背景・基準写真と同じ照明・靴底全体が入る。

## 4点タップ

順番固定で案内する: ①つま先の先端 ②かかとの先端 ③内側(親指側)の一番広い所 ④外側(小指側)の一番広い所。
タップ後に点はドラッグで微調整できる。左右どちらの靴でも、内側/外側で指定するので向きの区別は不要。

## 解析パイプライン（src/lib、すべて純粋関数）

入力は `{width, height, data: Uint8ClampedArray(RGBA)}` 形式の画像（ImageData 相当）。

1. **homography.js**: 4点 → 正規化座標への射影変換。
   正規化座標は u(横 0=内側〜1=外側), v(縦 0=つま先〜1=かかと)。
   対応: つま先=(0.5,0) かかと=(0.5,1) 内側最大幅=(0,0.35) 外側最大幅=(1,0.35)。
   4点がほぼ一直線など退化している場合はエラーを返す（UIで「点を打ち直して」）。
2. **warp.js**: 写真を正規化座標の固定解像度グレースケール画像（W=120, H=300）に双線形補間で再標本化。輝度は 0.299R+0.587G+0.114B。
3. **normalize.js**: 局所コントラスト正規化（ボックス窓で局所平均を引き、局所標準偏差で割る。σ下限あり）。明るさ・露出の差を吸収する。
4. **texture.js**: Sobel 勾配の大きさ → マス（12×30 グリッド、1マス=10×10px）ごとの平均＝模様の強さ。
5. **mask.js**: 靴底の形のマスク。正規化座標上の靴底テンプレート（つま先・最大幅・土踏まずのくびれ・かかとを通る滑らかな輪郭、u,v の関数）で外側を除外。さらに**基準画像で模様の強さがしきい値未満のマスは「判定不能」**（平らな部分は比較できない）。
6. **wear.js**: マスごとのすり減り度 = clamp(1 − 今/基準, 0, 1)。判定不能マスは null。
7. **regions.js**: 6部位に集計。部位の境界は v と u で定義:
   - つま先: v<0.18
   - 母趾球: 0.18≤v<0.42 かつ u<0.5
   - 小趾側: 0.18≤v<0.42 かつ u≥0.5
   - 土踏まず: 0.42≤v<0.68
   - かかと内: v≥0.68 かつ u<0.5
   - かかと外: v≥0.68 かつ u≥0.5
   部位ごとに平均と判定可能マスの割合を出す。判定可能マスが部位の 30% 未満なら部位の値は null（「判定不能」）。
   全体% = 判定可能マスの平均（各マスは同面積なので単純平均）。判定可能マスが全体の 25% 未満なら全体も null。
8. **quality.js**: 信頼度。正規化前の2画像について、平均輝度の差・ピント（ラプラシアン分散の比）を測る。
   どちらかが大きくずれていたら「低」とし、理由を文で返す（「今の写真が暗すぎます」「ピントが甘い」など）。値は 高/中/低。
9. **analyze.js**: 上記をつないだ入口 `analyze(baseImage, basePoints, nowImage, nowPoints) → {cells, regions, overall, quality}`。

## 表示

- ヒートマップ: 0%=緑 → 50%=黄 → 100%=赤、判定不能=斜線グレー。今の写真を正規化したものの上に半透明で重ねる。
- 部位カード6枚＋全体%の大きい数字。どれも「判定不能」はそう書く。
- 見方の注記: 「模様のくっきり具合の減り方から推定した値で、溝の深さを測ったものではありません」。

## 構成

```
src/lib/      純粋関数（上記）＋ storage.js（IndexedDB 薄いラッパ、テスト対象外）
src/app.js    画面の配線、window.__app を公開（ヘッドレス検証用: 画像と点を直接渡して解析できる）
src/ui/       画面ごとの描画（list / register / check / result / pointPicker）
```

## テスト（Vitest）

- homography: 既知の4点で往復一致、退化で例外。
- 合成画像: 縞模様の靴底を描いた基準画像と、一部領域の縞を消した（または振幅を半分にした）今画像を作り、
  消した部位のすり減り度が高く（>0.8／≈0.5）、触っていない部位が低い（<0.1）ことを確認。
- 明るさ違い: 今画像を全体に暗く（×0.6）しても触っていない部位のすり減りが低いまま（正規化の確認）。
- 回転・拡大して撮った今画像（4点も同じ変換）で結果がほぼ同じ。
- 判定不能: 模様のない基準領域は null、閾値割合未満で部位・全体が null。
- quality: 暗い/ぼけた画像で「低」と理由が返る。
